# Шаблон проекта: codeatlas.yaml

Файл в корне анализируемого проекта. Необязателен: без него программа берёт папку сборки `build` (а нет там compile_commands.json - ищет самый свежий в папках проекта до трёх уровней) и показывает общий C++ без компонентов.

Формат - плоский YAML: строки `ключ: значение` и `ключ: [a, b, c]`, комментарии через `#`. Вложенных разделов нет.

```yaml
# Имя проекта на карте (по умолчанию - имя папки)
name: VoxelGame

# Папка с compile_commands.json, от корня проекта или полный путь.
# CMake пишет его при set(CMAKE_EXPORT_COMPILE_COMMANDS ON) с генератором Ninja или Makefile.
# Нет его там - ищется в .codeatlas проекта, потом самый свежий в папках проекта и в соседних build-<проект>-... (Qt Creator)
compile_commands: build

# Папки от корня проекта, которые на карту не попадают (сторонние библиотеки и т.п.). Папка сборки не попадает и так
exclude: [Libs, Physics/Bullet3]

# Вызовы, чьи явные шаблонные аргументы - компоненты: registry.view<A, B>(), get<A>(e), emplace<A>(e) и т.п.
# Типы из них становятся компонентами (зелёные наклонные блоки), вызов - чтением компонента
component_calls: [view, get, try_get, emplace, emplace_or_replace, replace, patch, remove, erase, all_of, any_of]

# Из них - запись в компонент (остальные - чтение). const A в аргументах - всегда чтение
write_calls: [emplace, emplace_or_replace, replace, patch, remove, erase]

# Компонент с таким именем - событие (оранжевый наклонный блок)
event_regex: "_[ucdr]?Event$"
```

## Что считается связью

- Вызов: функция проекта вызывает другую функцию проекта (с определением в проекте). Номер - порядок первого вызова в теле среди таких вызовов. Вызовы из лямбд в теле считаются вызовами самой функции.
- Чтение: функция обращается к полю типа проекта (`a.x`, `p->x`) или берёт компонент вызовом из component_calls.
- Запись: поле в левой части присваивания (`=`, `+=` и т.п., в том числе перегруженных), под `++`/`--`, или компонент через write_calls.
- Поля своего класса в его методах связью не считаются - иначе каждый метод был бы связан со своим классом.

## Что лежит рядом с проектом

Папка `.codeatlas` в корне проекта:
- `layout.txt` - места блоков, пометки и вид камеры; можно хранить в git вместе с проектом
- `history/` - снимки графа по сканированиям (index.txt и графы), в git не кладётся (`.codeatlas/.gitignore` программа пишет сама)
- `compile_commands.json` - копия из папки сборки, если её туда кладёт сборка проекта (см. README); в git не кладётся

## Сканирование без окна

`CodeAtlas --scan <корень проекта> [--out <файл>]` - разбор и граф в текстовый файл (по умолчанию `.codeatlas/graph.txt`). Формат: строка `codeatlas-graph	1`, дальше строки узлов `N	id	вид	имя	полное имя	сигнатура	файл	строка	хэш тела	комментарий` и связей `E	id откуда	id куда	вид	порядок` через табуляцию (вид узла: 0 функция, 1 тип, 2 компонент, 3 событие; вид связи: 0 вызов, 1 чтение, 2 запись).
